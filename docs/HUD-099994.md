# HUD mechanics — 0.99994-dev

The previous presentation policy removed formula/resource prose from the common description, while the menu HUD displayed only that description. A nonempty F7 section did not establish that the menu HUD retained the action meaning. Static menu rows now include the native damage/healing type, element, readable formula and resource effects, even while numerical previews are deferred. The new acceptance suite exercises actual menu and enemy-selection rows.

Equal evasion bonuses share one row. Large sets of equal state rates retain every state in small named groups. Extra-command features are rendered as actual chances, and start-of-battle buffs/states are described once. Weakness explains its HP-recovery suppression. Granted evasive skills expose their bonuses. Anonymous rapier vulnerability states show their aggregated damage multiplier rather than record identities. Original game descriptions remain unchanged.

A fresh recorded three-Alice context reproduces the forecast refusal: one recipient counters, so the entire area sequence cannot be confirmed. The previous first-hit fallback still visited every recipient and inherited the same refusal. It now isolates the specified recipient before simulating one native application. This correction applies to all/random-target skills, not just Reaping. The HUD/F7 labels the current first hit; it does not present it as a complete series. Counter/reflection, possible death and unknown prior transitions still limit the full forecast. Area target count is no longer labelled as repeats per target.

The local numerical reconstruction uses the recorded actor, transformed enemy identity and parameters. It does not recover unrecorded native quick-use expenditure, state timers or random state. Controlled native first-hit samples and a separate zero-defence check validate the affected path independently. No enemy balance, action formulas, game data or native binaries are changed.
